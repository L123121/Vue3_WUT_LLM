# 面试口径：文档清洗管线（Document Cleaning Pipeline）

> **用途**：面试中回答"你们系统的数据入库前做了哪些清洗？"时的参考底稿。
> 每块标注【已实现】【设计层面】，方便按需取舍。

---

## 一、总览：五道已实现（ftfy 编码还原除外）

```
上传文档
  │
  ├─ 1. 字符级去脏 【已实现】  ← text-normalizer.service.js
  │     全角英数→半角（中文标点保留）、\u00A0/\u3000/\t/零宽 → 普通空格、
  │     \r\n → \n、BOM/控制字符剔除（保留 \n 与 \f 页分隔符）、
  │     乱码串（□■/\uFFFD/[UNK]/半角 ?{4,}/锟斤拷）→ 统一替换为 [UNK]
  │     ⚠️ ftfy 级编码还原【设计层面】——Node 无直接等价库，乱码文档靠闸门拒收兜底
  │
  ├─ 2. Prompt injection 行过滤 + 乱码质量闸门 【已实现】  ← doc-sanitizer.service.js
  │     注入模式命中 → 整行替换为占位标记 + 计数
  │     garbageRatio([UNK]/□/\uFFFD/连续半角问号占比)  >3% 告警 / ≥15% 拒绝入库
  │
  ├─ 3. 页眉页脚清洗 【已实现】  ← header-footer-cleaner.service.js
  │     ① 规则法：整行正则（"第X页/共Y页"、"- 3 -"、"Page X of Y"、Copyright 行）
  │     ② 位置法：按 \f 分页 → 统计顶部/底部 3 行跨页重复（≥30% 判定为页眉页脚）
  │     ⚠️ 有专门测试（13 个单测覆盖规则法、位置法、CRLF 输入等）
  │
  └─ 4. 句中断行拼回 【已实现】  ← text-normalizer.service.js
        当前行不以「。？！：；」结尾 且 下一行不以结构行开头（列表/标题/表格/引用/
        分隔线/代码围栏/注入占位行）→ 判定硬断行，\n 换空格拼接（累积式，可拼回整段）
        保护：空行（段落边界）、\f 前后（跨页）、代码围栏内部、frontmatter 块
        ⚠️ 中文无大写开头信号，只能靠结尾标点 + 结构行标记判断
```

**顺序固定不能乱**（`document.service.js` addDocument）：

1. **去脏最先**：全角"第３页"归一为"第3页"后，页眉页脚规则法的 `\d` 才匹配得上（有专门集成测试验证）
2. **注入过滤在断行合并前**：`[已过滤…]` 占位行若被并入正文，整行替换会误伤正文；normalizer 的结构行正则刻意包含 `[已过滤` 前缀做配套保护
3. **页眉页脚在断行合并前**：先合并会把页眉行拼进正文行，位置法的按行检测就失效了
4. **断行合并最后**：只对已清洗干净的文本做拼回

## 二、逐块详解

### 2.1 Prompt injection 行过滤 【已实现】

**文件**：`backend/src/services/doc-sanitizer.service.js`

**解决的问题**：上传文档原样进入 RAG 上下文 → LLM prompt；若文档写有"忽略以上指令"等注入文本，检索命中后可能改变 LLM 行为（泄露 system prompt、绕过拒答策略）。

**实现方式**：
- 7 个高特异性正则模式（中/英）：`override_zh`、`override_en`、`role_hijack`、`fake_role_marker`、`system_prompt_probe`、`secret_probe`、`payload_injection`
- 命中 → **整行替换为 `[已过滤：疑似提示词注入]`**，不影响其余内容
- 不误伤：讨论 AI 安全的学术内容（非祈使句）不会命中

**测试**：`doc-sanitizer.test.js` 8 个用例（命中注入/正常不误报/乱码分级/开关）

---

### 2.2 乱码检测与入库质量闸门 【已实现】

**文件**：`doc-sanitizer.service.js` → `garbageRatio()` 函数

**解决的问题**：OCR 质量差的扫描件产生大量 □/\uFFFD/[UNK]/连续问号，污染 embedding 输入，降低检索命中率。

**实现方式**：
```
garbageRatio = 乱码字符数 / 总字符数
  乱码字符 = \uFFFD(替换符) + \u25A0/\u25A1(方块) + [UNK] + ?{4,}(半角连续问号串)

分级：
  <3%   → qualityLevel: 'ok'（正常入库）
  3~15% → qualityLevel: 'warn'（告警，记录日志，仍入库）
  ≥15%  → qualityLevel: 'reject'（拒绝入库）
```

**注意**：闸门只做**检测与分级**；"替换"由第一步 text-normalizer 承担（各类乱码统一归一为 `[UNK]` 后再计量，替换→计量→闸门口径一致）。ftfy 类编码还原（锟斤拷还原原文）仍是设计层面——效果有限（仅针对 GBK/UTF-8 互读场景），乱码文档靠闸门拒收兜底。

**测试**：`doc-sanitizer.test.js` 专门覆盖 ok/warn/reject 三档。

---

### 2.3 页眉页脚清洗 【已实现】

**文件**：`backend/src/services/header-footer-cleaner.service.js`

**解决的问题**：每页残留的"第X页/共Y页"、"Copyright ©"、内编页码等重复文本：
- 所有切片相似度同量抬升 → 检索区分度下降
- 占用上下文 Token 预算（上限 6000 字）

**实现方式（双法串联，顺序固定）**：

| 方法 | 原理 | 适用场景 |
|------|------|----------|
| **规则法** | 整行正则匹配页码格式（`第X页`/`- X -`/`3/10`/`Page X of Y`）+ Copyright 行 → 整行删除 | 格式规范的页码行 |
| **位置法** | 按 `\f` 分页 → 统计顶部/底部各 3 行中跨页重复出现的行（≥30% 页出现 → 判定为页眉/页脚）→ 整行删除 | 非标格式页眉页脚（如"武理教务 第 N 页"） |

**位置法细节**（关键，面试加分）：
- 页码数字归一化：`第 N 页` → `第#页`，避免"2021年级/2022年级"仅差数字的正文行被误并
- 句末标点行（`。？！`结尾）不作为页眉/页脚候选 → 保护正文
- 短页（≤3行）不参与统计，也不被删空
- 无 `\f` 分页符时只跑规则法，位置法不执行

**清洗报告（`cleanReport`）**：存入文档 metadata，包含
- `pages`（页数）、`removedRuleLines`/`removedPositionLines`（命中行数）
- `ruleSamples`/`headerSamples`/`footerSamples`（样例行，可审计）

**测试**：`header-footer-cleaner.test.js` **13 个单测**（规则法/位置法/CRLF 输入/短页保护/数字归一化等）

### 2.4 字符级去脏 【已实现，ftfy 还原除外】

**文件**：`backend/src/services/text-normalizer.service.js` → `normalizeCharacters()`

**解决的问题**：PDF/DOCX 抽取的文本常混有全角英数（"第３页"）、非常规空白（\u00A0/\u3000/零宽字符）、BOM、控制字符和 OCR 乱码。全角数字会让页眉页脚规则法的 `\d` 失配；非常规空白打断 embedding 的分词一致性；乱码直接污染向量。

**实现方式**（单趟顺序固定）：
1. `\r\n`/孤立 `\r` → `\n`
2. 剔除 BOM `\uFEFF`
3. 剔除控制字符（**保留 `\n` 与 `\f`**——`\f` 是 pdf-parse 的页分隔符，位置法按它分页）
4. 全角→半角：**仅英文字母与数字**（`Ａ→A`、`０→0`）。`！？：；` 等全角形态在中文文本里就是中文标点，转了会破坏 embedding 一致性——刻意收窄
5. 乱码归一：□■/\uFFFD/[UNK] 连串、半角 `?{4,}`、锟斤拷 → 统一替换为 `[UNK]` 并计数（**不含全角 `？` 串**——中文网络语气"？？？？"是正常表达，替换会污染正文）
6. 非常规空白 → 普通空格

报告写入 metadata（`normalizeReport`：fullwidth/whitespace/bom/control/garbageReplaced/mojibakeReplaced 计数），可审计。

**测试**：`text-normalizer.test.js` 覆盖各类计数、`enabled=false` 旁路、全角问号串保留等。

---

### 2.5 句中断行拼回 【已实现】

**文件**：`backend/src/services/text-normalizer.service.js` → `mergeHardLineBreaks()`

**解决的问题**：PDF 转换常把句子拦腰截断（如"重\n要"），切断的句子各自成 chunk 后，embedding 语义不完整，检索命中率下降。

**实现方式**：
- 判定：当前行不以句末标点（`。？！：；`，剥掉行尾引号/括号后再判）结尾，且下一行不以结构行开头 → 硬断行，`\n` 换空格拼接
- **累积式合并**：合并后的行继续参与下一轮判定，一段被切碎的段落能完整拼回一行
- 保护不合并：下一行为列表序号/Markdown 标题/表格行/引用/分隔线/代码围栏/注入占位行；当前行为标题/表格/引用；空行（段落边界）；`\f` 前后（跨页）；代码围栏内部（代码的 `\n` 与缩进是语义）；frontmatter 块

**实现踩过的坑**（面试加分）：跨页保护最初写成 `/\f$/.test(line.trimEnd())`——`\f` 本身是空白字符，`trimEnd()` 会把它一并 trim 掉，守卫永不生效；改为 `/\f\s*$/.test(line)` 才正确。测试先行捕捉了这个 bug。

**测试**：`text-normalizer.test.js` 覆盖链式合并、六类结构行保护、围栏状态机、frontmatter、`\f` 跨页两个方向、注入占位行保护、与页眉页脚清洗器的跨服务集成。

## 三、面试讲法（30 秒版 + 2 分钟版）

### 30 秒版（一句话带过每个点）

> 入库前做四道清洗：① 字符级去脏（全角英数归一、非常规空白统一、乱码统一替换 [UNK]，全角数字归一后页眉页脚规则法才匹配得上）；② Prompt injection 行过滤（7 个注入模式正则，命中整行替换占位标记）+ 乱码质量闸门（[UNK] 占比超 15% 拒绝入库）；③ 页眉页脚双法清洗（规则法正则 + 位置法跨页重复行检测，13 个单测）；④ 句中断行拼回（句末标点 + 结构行标记判定硬断行，累积式拼回整段）。唯一没做的是 ftfy 级编码还原，Node 没有直接等价库，乱码文档靠闸门拒收兜底。

---

### 2 分钟版（适合追问展开）

> 文档入库前的清洗分四层，顺序固定不能乱：
>
> **第一层：字符级去脏。** PDF/DOCX 抽取的文本常混有全角英数、非常规空白和乱码。全角英数转半角——但刻意只转字母和数字，`！？：；` 的全角形态在中文里就是中文标点，转了反而破坏 embedding 一致性。这一步必须最先做：全角"第３页"归一成"第3页"之后，后面页眉页脚规则法的 `\d` 才匹配得上。乱码（方块、替换符、锟斤拷、半角连续问号）统一替换成 `[UNK]` 标记——全角问号串刻意排除，"？？？？"在中文里是正常语气词，替换会污染正文。
>
> **第二层：Prompt injection 过滤 + 乱码闸门。** 注入用 7 个高特异性正则（中英双语，涵盖指令覆写、角色劫持、伪造 system 标记、密钥探测、script payload），命中一行替换一个 `[已过滤]` 占位标记，不影响其他内容；不误伤讨论 AI 安全的学术内容，因为模式都是祈使句特征。乱码闸门统计 `[UNK]`/方块/替换符占比，超 3% 告警，超 15% 直接拒绝入库——normalizer 把乱码归一成 `[UNK]` 之后，闸门在归一化后的文本上计量，"替换→计量→闸门"口径一致。
>
> **第三层：页眉页脚清洗。** 双法串联——规则法先删格式规范的页码行，然后位置法按 `\f` 分页符切页，统计每页顶部/底部 3 行中跨页重复出现的行（≥30% 页出现才判定），重复行整行删除。位置法的关键细节：数字归一化（`第 N 页` → `第#页`），句末标点行不作候选（保护正文），短页不参与统计不被删空。有 13 个单测专门覆盖边界情况。
>
> **第四层：句中断行拼回。** PDF 常把句子拦腰截断，各自成 chunk 后 embedding 语义不完整。判定条件：当前行不以句末标点结尾、且下一行不是结构行（列表序号/标题/表格/引用/代码围栏）→ 硬断行，`\n` 换空格拼接，累积式合并能一次拼回整段。中文没有大写开头信号，只能靠结尾标点 + 结构行标记。踩过一个坑：跨页保护一开始用 `trimEnd()` 后判 `\f`，但 `\f` 本身是空白，被 trim 掉了守卫就永不生效——测试先行把这个 bug 抓了出来。
>
> **坦白没做的：** ftfy 级编码还原（锟斤拷还原为原文）——Node 生态没有 ftfy 的直接等价库，还原效果也有限（只针对 GBK/UTF-8 互读场景），所以乱码文档靠闸门拒收兜底，不在管线里硬做修复。
>
> 清洗只在入库前做一遍，检索和生成阶段不再动文本，保证 embedding 输入和进 LLM 上下文的文本完全一致。

## 四、面试常见追问与回答

**Q: 清洗步骤的顺序为什么不能乱？**
> A: 三条硬约束：① 去脏必须在页眉页脚之前——规则法靠 `\d` 匹配"第3页"，全角"第３页"不归一就匹配不上（有专门集成测试验证）；② 注入过滤必须在断行合并之前——`[已过滤]` 占位行若被并入正文，整行替换会误伤正文，断行合并的结构行正则也刻意包含 `[已过滤` 前缀做双保险；③ 页眉页脚必须在断行合并之前——先合并会把页眉行拼进正文行，位置法的按行检测就失效了。

**Q: 页眉页脚怎么处理重复但内容不同的情况（如页码）？**
> A: 位置法统计时做数字归一化——`第 N 页` 中的 N 统一替换为 `#`，这样"第 1 页"和"第 12 页"在归一化后变成同一个字符串，能被正确识别为跨页重复。同时有句末标点守卫：如果一行以句号/问号/叹号结尾，即便内容跨页重复，也不判定为页眉页脚（保护正文句）。

**Q: Prompt injection 过滤的正则会不会误杀正常文档？**
> A: 故意保持高特异性，每个模式都是祈使句+特定关键词组合（如"忽略以上所有指令"），不是简单的黑名单词表。测试里专门验证了讨论 AI 安全的学术内容（"Prompt injection 是指……""研究表明，防御注入攻击需要……"）都不会命中。

**Q: 乱码闸门为什么要 warn 和 reject 两级？直接 reject 不行？**
> A: 3%~15% 是灰色地带——少量乱码可能只是几个生僻字被 OCR 识别错了，不影响整体质量，直接拒绝入库会损失有用信息。warn 级别记日志让管理员看到，可以人工决定是否补充 OCR 或手动修复后重传。

**Q: 断行拼回怎么避免把代码块、列表、表格拼坏？**
> A: 六类结构行保护 + 围栏状态机：下一行是列表序号/Markdown 标题/表格/引用/分隔线/代码围栏就不并入；当前行是标题/表格/引用不外吸；` ``` ` 围栏内部用状态机整体跳过（代码的换行和缩进是语义）；空行视为段落边界；`\f` 前后跨页不合并；frontmatter 块整体跳过。列表项刻意**允许**与续行合并——列表条目被硬换行切碎正是要修复的对象。
