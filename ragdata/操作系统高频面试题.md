# 操作系统高频面试题

> 大厂后端/通用软件岗操作系统高频题，按"进程线程 → 内存 → 中断与内核"三块整理，答案给要点框架，展开讲 1-2 分钟。

## 一、进程与线程

### 1. 进程和线程的区别？什么时候用多进程、什么时候用多线程？

- 定位：进程是资源分配单位，线程是调度执行单位。
- 资源：线程共享进程的地址空间与打开文件，独享栈和寄存器上下文。
- 开销：进程切换要换页表/刷新 TLB，成本高；线程切换只换栈与寄存器。
- 健壮性：一个线程崩溃可能拖垮整个进程；多进程故障隔离好。
- 选型：CPU 密集且需隔离（如 Chrome 多进程渲染）；需要大量共享数据低延迟通信选多线程；Node/Redis 用单线程事件循环避免锁竞争。

### 2. 进程间通信方式对比？

| 方式 | 特点 | 适用 |
|------|------|------|
| 管道 | 半双工、亲缘进程（匿名）；命名管道无亲缘限制 | 父子进程流式数据 |
| 消息队列 | 有格式边界、可按类型取 | 小消息解耦 |
| 共享内存 | 最快（零拷贝），需配信号量同步 | 大量数据高频交换 |
| 信号量 | 本质是同步原语不是传数据 | 配合共享内存 |
| socket | 跨主机通用 | 网络/本机均可 |

### 3. 协程是什么？和线程的区别？

用户态轻量级执行单元，切换由程序/运行时调度（不需要陷入内核），栈可按需 KB 级分配。单线程内成千上万协程靠事件循环驱动；缺点是不能利用多核（需 M:N 调度）且阻塞调用会卡住整个循环。Go goroutine、Python asyncio、Kotlin 协程都是落地。

### 4. 什么是僵尸进程、孤儿进程？怎么处理？

- 僵尸：子进程退出后父进程没 wait() 回收，残留 PCB 占 PID。处理：父进程补 wait/waitpid，或杀掉父进程让 init 收养回收。
- 孤儿：父进程先亡，子进程被 init/systemd 收养继续运行，无资源泄漏问题。

### 5. select/poll/epoll 的区别？

| 维度 | select | poll | epoll |
|------|------|------|------|
| fd 上限 | 1024 | 无硬限 | 无硬限 |
| 内核拷贝 | 每次全量传入 | 全量 | 事件驱动就绪链表 |
| 复杂度 | O(n) 扫描 | O(n) | O(1) 取就绪 + 回调 |
| 触发模式 | LT | LT | LT/ET |

epoll 适合海量连接少量活跃（长连接网关）；select/poll 适合连接少且跨平台场景。

## 二、内存管理

### 6. 虚拟内存的作用与实现？

每个进程有独立虚拟地址空间，MMU 通过页表完成 VA→PA 转换。作用：隔离保护、内存超额分配（换页）、共享映射（动态库）。实现：请求分页 + 页面置换 + swap。

### 7. 缺页中断的全过程？缺页一定不好吗？

访问未映射页 → MMU 触发 page fault → 内核检查合法性 → 装入页框/置换脏页写回 → 更新页表 → 重执行指令。首次访问 mmap 区、写时复制 COW 都依赖合法缺页——**缺页不等于错误**，只有非法访问才 SIGSEGV。

### 8. malloc 的内存是怎么来的？

小于阈值（默认 128KB）用 brk 在堆顶扩展，走 ptmalloc 的 bin 复用；大块用 mmap 单独映射，释放即 munmap 归还 OS。free 不一定归还物理内存（glibc 收缩阈值），所以"free 了内存没降"不等于泄漏。频繁大对象建议内存池或直接 mmap 管理。

### 9. 什么是内存泄漏、内存溢出？如何排查？

- 泄漏：申请后不再使用却未释放，长期累积导致可用内存下降。
- 溢出 OOM：申请时无足够内存。
- 排查工具链：valgrind / AddressSanitizer / jemalloc profile / pmap+smaps 分析 RSS 构成；线上看 /proc/pid/status 与监控趋势。

### 10. 页面置换算法有哪些？LRU 怎么工程实现？

OPT/FIFO/LRU/Clock。LRU 工程实现 = 哈希表 + 双向链表（O(1) 访问与淘汰），Redis 的近似 LRU 是采样淘汰而非严格 LRU，权衡精度与开销。

### 11. CPU 缓存一致性与伪共享？

多核各自 L1/L2，MESI 协议保证缓存行一致性。伪共享：两个无关变量落在同一 64B 缓存行被不同核反复失效——解决：alignas(64) 缓存行对齐填充（Java @Contended）。高并发计数器、无锁结构必考细节。

## 三、中断、内核与系统编程

### 12. 用户态和内核态切换的开销在哪里？

保存/恢复寄存器现场与内核栈切换、权限级切换（CPU pipeline flush 部分）、TLB/分支预测失效的间接损耗。一次系统调用约几百 ns~1μs，因此高并发网络编程追求批量 syscall（io_uring/sendmmsg）减少往返。

### 13. 零拷贝是什么？有哪些技术路径？

传统 read+write 四次拷贝四次切换；优化：

- mmap+write：减少一次 CPU 拷贝；
- sendfile：数据全程在内核态流转；
- sendfile + DMA gather（splice）：仅 2 次 DMA 拷贝，0 次 CPU 拷贝。
适用静态文件分发（nginx sendfile on）、Kafka 日志传输；需要加工数据时不适用。

### 14. fork 返回两次是怎么回事？写时复制？

fork 在父子进程中各返回一次（父得子 PID，子得 0）。现代 OS 用 COW：初始共享物理页标记只读，任一方写入才触发缺页复制页面——降低 fork 成本，Redis RDB 持久化正是利用它快照全量数据。

### 15. 平滑重启服务时旧连接怎么处理？

典型方案：master fork worker（继承 listen fd）→ 新 master 起新 worker，老 worker 先 stop accept、处理完存量请求再退出（优雅关闭），配合 SO_REUSEPORT 或信号传递。考察点：fd 继承、半关闭 shutdown 与超时兜底。

## 四、综合设计题

### 16. 设计一个高并发短连接网关要注意哪些 OS 层面的问题？

1. fd 上限与 SO_REUSEADDR/SO_REUSEPORT；
2. TIME_WAIT 过多：长连接化、端口段扩大、tcp_tw_reuse；
3. backlog 与 accept 队列打满丢包；
4. epoll ET + 非阻塞 + 用户态缓冲组装；
5. 内存池避免频繁 malloc/free；
6. 优雅退出与连接排空。

### 17. 如何理解"一切皆文件"？

VFS 抽象统一了磁盘文件、设备、管道、socket、eventfd 等，提供 open/read/write/ioctl 统一接口；好处是复用同一套 I/O 多路复用与重定向机制（如把日志写到 eventfd/管道即可接入统一事件循环）。
