# 前端高频面试题整理（八股文版）

> 汇总大厂前端面试中的高频基础题，按 HTML/CSS、JavaScript、框架、工程化四部分整理，附标准答案要点。

## 一、HTML 与 CSS

### 1. 盒模型

- 标准盒模型：width = content；IE 盒模型（border-box）：width = content + padding + border。
- 通过 `box-sizing: border-box` 让 IE 盒模型生效，布局更可控。

### 2. 水平垂直居中

```css
/* 方案一：flex */
.parent { display: flex; align-items: center; justify-content: center; }
/* 方案二：绝对定位 + transform */
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }
```

### 3. 回流（Reflow）与重绘（Repaint）

- 改变布局属性（宽高、边距、定位）触发回流；改变颜色、背景等仅触发重绘。
- 优化：批量修改 DOM、使用 `display:none` 后操作再显示、`will-change` 提示浏览器。

## 二、JavaScript

### 1. 事件循环（Event Loop）

- 宏任务：setTimeout、setInterval、I/O；微任务：Promise.then、MutationObserver、queueMicrotask。
- 执行顺序：同步代码 → 微任务 → 宏任务，宏任务执行完后会清空当前微任务队列。

### 2. 闭包

- 闭包 = 函数 + 函数定义时的词法环境。用于数据私有化、函数柯里化、防抖节流。
- 内存泄漏：闭包引用的大对象长期不被释放，可通过置空引用解决。

### 3. 防抖与节流

```js
// 防抖：触发后延迟执行，多次触发只执行最后一次
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
// 节流：固定时间间隔内只执行一次
function throttle(fn, interval) {
  let last = 0;
  return function (...args) {
    const now = Date.now();
    if (now - last >= interval) { last = now; fn.apply(this, args); }
  };
}
```

### 4. 原型链与 this

- `__proto__` 指向构造函数的 `prototype`，实例查找属性沿原型链向上。
- this 指向：普通函数调用指向调用者，箭头函数继承外层 this，new 绑定新对象。

## 五、浏览器与网络进阶

### 1. 从输入 URL 到页面展示发生了什么？

DNS 解析（缓存→递归查询）→ TCP 三次握手/TLS 握手 → 发送 HTTP 请求 → 服务端处理响应 → 浏览器解析：构建 DOM 树与 CSSOM → 合成渲染树 → Layout 回流 → Paint 重绘 → Composite 合成。优化抓手：DNS 预解析、HTTP/2 多路复用、关键渲染路径（首屏 CSS 内联、JS defer/async）。

### 2. HTTP/1.1、HTTP/2、HTTP/3 的核心差异？

- 1.1：文本协议，队头阻塞（同一 TCP 连接串行），靠域名分片缓解；
- 2：二进制分帧 + 多路复用解决 HTTP 层队头阻塞，头部压缩 HPACK，服务器推送；但 TCP 层队头阻塞仍在；
- 3：基于 QUIC(UDP)，流级别独立丢包重传消除 TCP 队头阻塞，0-RTT 建连。

### 3. 强缓存与协商缓存在实践中的组合策略？

HTML 入口用 `no-cache` 走协商保证新鲜；带 hash 的静态资源 `Cache-Control: max-age=31536000, immutable` 一年强缓存；接口按业务用 `no-store` 或短 max-age。发布回滚安全由"文件名指纹不可变"保证。

### 4. XSS 与 CSRF 的区别和防御？

- XSS：注入脚本执行。防御：输出转义、CSP 内容安全策略、HttpOnly Cookie、避免 v-html 未过滤内容。
- CSRF：伪造用户请求。防御：SameSite=Lax/Strict Cookie、CSRF Token 校验 Origin/Referer、敏感操作二次验证。
- 二者本质不同：XSS 偷信任执行代码，CSRF 冒用身份发请求。

### 5. WebSocket 与 SSE 的取舍？

WebSocket 全双工、二进制帧、需独立协议升级；SSE 基于 HTTP 单向服务端推送，自动重连 + text/event-stream，实现成本低。聊天双工选 WS；AI 流式回答、行情推送这类单向流选 SSE（本项目 RAG 流式回答即 SSE）。

## 六、Vue 框架深入

### 1. Vue3 响应式原理：Proxy 比 defineProperty 强在哪？

Proxy 劫持整个对象，支持新增/删除属性、数组索引与 length 监听、Map/Set；惰性代理嵌套对象（访问时才深层代理）初始化更快。依赖收集：track 在 getter 中记录 activeEffect，set 中 trigger 派发更新；effect 存在 WeakMap<target, Map<key, Set<effect>>> 结构中。

### 2. ref 与 reactive 的选择？

reactive 只能包对象且解构丢失响应式（需 toRefs）；ref 通过 .value 访问可包装任意类型，是跨边界传递的统一形态。实践：组合函数入参出参用 ref/reactive 各有惯例，但对外暴露状态优先 ref。

### 3. Composition API 解决了什么问题？

Options API 按选项组织代码导致同一业务逻辑分散在 data/methods/computed 各处，大组件难维护。Composable 把"状态+计算+副作用"按逻辑单元聚合复用（如 useStreaming 封装 SSE），替代 mixin 的命名冲突与来源不清晰问题。

### 4. keep-alive 与组件缓存原理？

内置组件以 key 缓存 vnode 到 cache Map，命中时跳过重新渲染直接恢复，配合 activated/deactivated 钩子做数据刷新；LRU 策略限制缓存数量防止内存膨胀。列表页→详情页返回保持滚动位置即典型应用。

### 5. diff 算法中 key 的作用？

同层比较时通过 key 判断节点是否可复用；无 key 用就地复 patch（内容全量比对），有 key 才能做最长递增子序列的最小移动优化。常见坑：随机 key/index 作 key 导致状态错乱与多余重建。

## 七、TypeScript

| 问题 | 答案要点 |
|------|------|
| interface vs type | interface 可声明合并、可被 extends；type 支持联合/交叉/条件/映射等类型运算；对象形状两者皆可，工具类型必须 type |

| 常用工具类型 | Partial/Required/Pick/Omit/Record/ReturnType/Parameters，手写实现是高频题 |
| 类型收窄手段 | typeof/instanceof/in 字面量判别联合、非空断言的克制使用 |

## 八、前端工程化与性能

### 1. Vite 为什么比 webpack 快？

开发态基于原生 ESM 按需编译：请求哪个模块才转换哪个（esbuild 预构建依赖，Go 实现 10-100x 快）；webpack 需要先打包完整 bundle 再启动。生产态 Vite 默认 Rollup 打包，产物质量与生态兼容是选型考量点。

### 2. 首屏性能优化清单（按收益排序）

1. 网络：CDN、HTTP/2、资源压缩（brotli）、合理强缓存；
2. 体积：路由懒加载、Tree Shaking、按需引入组件库、分析 bundle（rollup-plugin-visualizer）；
3. 渲染：SSR/SSG 或骨架屏、图片懒加载+webp、关键 CSS 内联；
4. 度量闭环：Lighthouse / web-vitals（LCP、CLS、INP），先测后优。

### 3. 长列表渲染怎么优化？

虚拟滚动：只渲染可视区±缓冲区的 DOM，滚动时用 transform/padding 撑起总高度并动态计算起始索引；不定高场景需测量缓存行高做预估修正。配合消息场景的分页拉取与 Markdown 渲染缓存效果更佳。

### 4. 微前端的理解与取舍？

多团队独立部署聚合到同一壳应用。方案对比：qiankun（沙箱+single-spa 成熟）、Module Federation（构建期共享模块）、Web Components（原生隔离）。代价：样式/JS 沙箱开销、公共依赖治理、通信复杂度——单体够用时不必上微前端。
