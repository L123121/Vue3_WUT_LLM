## 第一章 概述

### 1. 分层体系结构

| 体系结构 | 说明 | 分层（从上到下） |
|----------|------|------------------|
| ISO/OSI | 法律标准 | 应用层、表示层、会话层、**运输层**、网络层、数据链路层、物理层 |
| TCP/IP | 事实标准 | 应用层、**运输层**、网际层、网络接口层 |
| **五层协议** | **考试标准** | **应用层、运输层、网络层、数据链路层、物理层** |

**通信子网** = 网络层 + 数据链路层 + 物理层（负责数据传输）
**资源子网** = 应用层 + 运输层（负责数据处理）

### 2. 计算机网络性能指标

| 时延类型 | 公式 |
|:--------:|:----:|
| **发送时延** | 数据帧长度(bit) / 发送速率(bit/s) |
| **传播时延** | 信道长度(m) / 信号传播速率(m/s) |

**总时延** = 发送时延 + 传播时延 + 处理时延 + 排队时延
**时延带宽积** = 传播时延 × 带宽

> ❗ 发送时延在机器内部，取决于数据长度；传播时延在线路上，取决于物理距离

### 3. 电路交换 vs 分组交换

| 特性 | 电路交换 | 分组交换 |
|:----:|:--------:|:--------:|
| 连接 | 建立专用通路 | 无连接（存储转发） |
| 实时性 | 好 | 较好 |
| 线路利用率 | **低** | **高**（统计复用）|
| 应用 | 电话网络 | **互联网核心采用** |

**计算对比**：
```
电路交换总时延 = 连接建立时间 + 发送时延 + 传播时延
分组交换总时延 = 发送时延 + 存储转发时延(k-1个分组) + 传播时延
```

### 4. 互联网基础结构

**ISP**（Internet Service Provider）：互联网服务提供商
**C/S**（Client/Server）：客户-服务器方式 | **P2P**（Peer-to-Peer）：对等方式

## 第二章 物理层

### 1. 数字信号与模拟信号

- **数字信号**：离散（0/1），计算机处理 | **模拟信号**：连续，传统通信
- **基带信号**：来自信源的原始信号，不能直接在信道中传输

### 2. 比特率与波特率

```
比特率 = 波特率 × 码元信息量
```
- 比特率：bps | 波特率：Baud（码元/秒）
- 二进制编码：1码元=1bit → 比特率=波特率

### 3. 奈氏准则与香农公式

**奈奎斯特（理想无噪声信道）**：
```
最大数据传输率 = 2W × log₂K (bps)    W=带宽(Hz), K=电平数
```

**香农公式（有噪声信道）**：
```
C = W × log₂(1 + S/N) (bps)
信噪比(dB) = 10 × log₁₀(S/N)    S/N = 10^(dB/10)
```

**实际最大速率 = min(奈奎斯特值, 香农值)**

### 4. 基带调制、带通调制、曼彻斯特编码

| 操作 | 输入→输出 |
|:----:|:----------:|
| 基带调制（编码） | 数字信号→数字信号 |
| 带通调制 | 数字信号→模拟信号 |

| 编码 | 规则 | 自同步 | 应用 |
|:----:|:----:|:------:|:----:|
| **曼彻斯特** | 中间上跳=0, 下跳=1, **中必变** | ✅ | **以太网** |
| 差分曼彻斯特 | 开头跳=0, 不跳=1, **中必变** | ✅ | 令牌环网 |

### 5. 传输媒体

**同轴电缆**（有线电视）→ **双绞线**（局域网）→ **单模光纤**（远距离、激光器）→ **多模光纤**（短距离、LED）

> 光纤：全反射原理，**单向通信**

### 6. 常用复用技术

**FDM**（频分）→ **TDM**（固定时隙）→ **STDM**（动态分配）→ **WDM**（光的FDM）→ **CDMA**（码片正交）

### 7. 数字调制技术（ASK / FSK / PSK）

**带通调制的三种基本方法**（数字信号→模拟信号）：

| 调制方式 | 对应模拟调制 | 原理 | 特点 |
|:--------:|:-----------:|:----:|:----:|
| **ASK**（振幅键控） | 调幅（AM） | 不同振幅代表 0/1（如振幅 0 → "0"，有振幅 → "1"） | 易受干扰 |
| **FSK**（移频键控） | 调频（FM） | 不同频率代表 0/1（如 f₁ → "0"，f₂ → "1"） | 抗干扰较强 |
| **PSK**（移相键控） | 调相（PM） | 不同相位代表 0/1（如 0° → "1"，180° → "0"） | 抗干扰最强 |

> ASK 对应 AM，FSK 对应 FM，PSK 对应 PM —— 均为将数字信号调制到模拟载波上的基本方法，属于**带通调制**。

### 8. CDMA 码分多址原理（⚠️ **常考计算**）

**核心原理**：每个站点分配一个唯一的码片序列（相互正交），多个站点可同时发送。接收方用目标站点的码片序列与收到的混合信号做**规格化内积**：
- 结果为 **+1** → 发送比特 **1**
- 结果为 **−1** → 发送比特 **0**
- 结果为 **0** → 该站点未发送

**码片正交条件**：不同站点的码片序列向量内积为 0，自身内积为 1（规格化）。

---

**【典型例题】**

站点 A、B、C 通过 CDMA 共享链路，A、B、C 的码片序列分别是 `(1, 1, 1, 1)`、`(1, −1, 1, −1)` 和 `(1, 1, −1, −1)`。若从链路上收到的序列是 `(2, 0, 2, 0, 0, −2, 0, −2, 0, 2, 0, 2)`，则收到 A 发送的数据是（ ）

A. 000 &emsp; B. **101** &emsp; C. 110 &emsp; D. 111

**解析**：

码片长度为 4，将接收序列每 4 位分成一组：

| 分组 | 接收序列 |
|:---:|:--------:|
| R₁ | (2, 0, 2, 0) |
| R₂ | (0, −2, 0, −2) |
| R₃ | (0, 2, 0, 2) |

计算 A 的数据（码片 Sₐ = (1, 1, 1, 1)）：

```
第1位：(2×1 + 0×1 + 2×1 + 0×1) / 4 =  4/4 = +1 → 1
第2位：(0×1 + (−2)×1 + 0×1 + (−2)×1) / 4 = −4/4 = −1 → 0
第3位：(0×1 + 2×1 + 0×1 + 2×1) / 4 =  4/4 = +1 → 1
```

结果：(+1, −1, +1) → 二进制 **101**

✅ **正确答案为 B**

## 第三章 数据链路层

### 1. CRC循环冗余检验（⚠️ **必考计算**）

- **检错码**：只能检测不能纠正（如CRC）
- **生成多项式** r+1位 → 校验位 = **r位**

**计算步骤**：
1. 信息位后添加 r 个0 → 被除数
2. **模2除法**（异或）→ 得 r 位余数
3. 发送数据 = 信息位 + 余数
4. 接收端：收到的数据 ÷ 生成多项式，余数为0则正确

> **模2加 = 异或**：1+1=0，0+1=1，不进位

### 2. 帧定界方法（透明传输）

| 方法 | 适用链路 | 原理 | 示例 |
|:----:|:--------:|:----|:----:|
| **字节填充法** | 异步传输（面向字符） | 在数据中所有界定符和转义字符前面，再加一个转义字符 | 界定符为 `7E`，数据中出现 `7E` → 填充为 `7D 5E` |
| **0比特填充法** | 同步传输（面向比特） | 扫描数据，发现连续5个1 → 自动插入一个0 | `01111110` 中的连续6个1被破坏，接收端自动删除填充的0 |

> 两种方法的目标都是实现**透明传输**：确保数据中任何比特组合都不会被误判为帧定界符。

### 3. PPP协议（0比特填充）

- 帧定界符：`7E`（`01111110`）
- **透明传输**：数据中出现连续5个1 → 自动插入一个0
- PPP 同时支持**字节填充**（异步链路）和 **0比特填充**（同步链路）

### 4. CSMA/CD协议（⚠️ **重要**）

**要点**：多点接入 + 载波监听 + 碰撞检测 | **只能半双工**

> **⚡ CSMA/CD 正常工作的铁律：发送时延 ≥ 往返时延（2τ）**
> 即：帧还没发完，信号就已经能跑个来回。这样才能确保发送过程中检测到碰撞。
> **最短帧长 = 数据率 × 2τ**，三者知二求一。

**争用期**：以太网 2τ = **51.2μs**
**最短帧长** = 2τ × 速率 = **64字节**
**退避算法**：碰撞后从 {0,1,...,2ᵏ-1} 选 r，等 r×2τ 后重传（k=min(重传次数,10)），超16次丢弃

#### 📝 经典例题：CSMA/CD 最短帧长计算

**【题目】** 假定 **1km** 长的 CSMA/CD 网络的数据率为 **1Gb/s**。设信号在网络上的传播速率为 **200,000km/s**。求能够使用此协议的最短帧长。

**【原理】** 帧的发送时延 ≥ 争用期（往返传播时延 2τ），确保发送完毕前能检测到冲突：
```
最短帧长 = 数据率 × 争用期 = R × 2τ      其中 τ = d / v
```

**【计算】**

| 步骤 | 计算 | 结果 |
|:----:|:----|:----:|
| ① 单程 τ | τ = 1 / 200,000 | = **5 μs** |
| ② 争用期 2τ | 2 × 5 μs | = **10 μs** |
| ③ 最短帧长 L | 10⁹ bps × 10⁻⁵ s | = **10,000 bit = 1250 字节** |

**【⚠️ 易错点】**
- 速率单位用 **10⁹**（1G = 10³M = 10⁶k = **10⁹**，不是 1024³）
- 别漏了 **2τ** 中的 **2**——CSMA/CD 用**往返**时延
- **公式变形**：帧长/带宽 = 2×距离/传播速度，三个量知二求一

#### 💡 指数退避算法速记

| 要点 | 内容 |
|:----:|:----|
| **基本退避时间** | = **争用期 2τ**（以太网 = **51.2μs**），是退避的最小时间单位 |
| **范围公式** | 第 k 次重传从 `{0, 1, ..., 2ᵏ−1}` 中随机选 r，等待 r × **基本退避时间**（即 r × 2τ） |
| **上限** | k = min(重传次数, **10**)，即最大范围 0~1023 |
| **丢弃** | 重传超 **16次** 仍失败 → 丢弃帧，向上层报告 |
| **目的** | 动态调整等待时间，降低再次碰撞概率 |

> 选择题考点：范围上限是 10（不是 16），丢弃阈值是 16。**基本退避时间 = 2τ（争用期）**，不是 τ。

### 5. 网桥、以太网交换机工作原理

| 设备 | 层次 | 隔离冲突域 | 隔离广播域 |
|:----:|:----:|:----------:|:----------:|
| 集线器 | 物理层 | ❌ | ❌ |
| **网桥/交换机** | 数据链路层 | ✅ | ❌ |
| **路由器** | 网络层 | ✅ | ✅ |

> 交换机根据 **MAC地址表**（自学习建立）转发帧

#### 5.1 交换机自学习与转发机制核心总结

**两大核心动作**

| 动作 | 依据 | 做法 |
|:----:|:----:|:------|
| **学习** | 帧的 **源MAC地址** | 记录"源MAC → 接收端口"到帧交换表 |
| **转发** | 帧的 **目的MAC地址** | 查表决定从哪个端口转发 |

**转发决策规则**

| 查表结果 | 处理方式 | 别名 |
|:--------:|:--------:|:----:|
| **找到**目的MAC | 只从对应端口转发 | **单播**（精准送达） |
| **找不到**目的MAC | 从除接收口外的所有端口转发 | **泛洪**（广播找人） |

**整张表怎么来的？**

> **靠"源MAC"慢慢学习积累，不是预先配置的。**

- 每个交换机**独立学习**，只记录自己实际收到的帧的源MAC
- 没收到帧 → 表里就没有该MAC → 只能泛洪
- 学习到了 → 下次再发给它 → 直接单播转发

**一句话终极总结**

> **学习靠"源MAC"，转发查"目的MAC"；表里有 → 直接用，表里无 → 广播找。**

### 6. VLAN（虚拟局域网）

- 将一个物理局域网在逻辑上划分成多个虚拟局域网
- **隔离广播域**，不同VLAN间通信需经**路由器**
- VLAN划分与**交换机**密切相关

## 第四章 网络层

### 1. 网络层功能、路由器作用

**网络层功能**：路由选择 + 分组转发 | **路由器**：连接不同网络，实现转发和选路

### 2. IP数据报格式（分片）（⚠️ **重要**）

**首部固定20字节**，可选字段最长40字节，总长20~60字节。

| 关键字段 | 长度 | 说明 |
|:--------:|:----:|------|
| **版本** | 4位 | IPv4=4 |
| **首部长度** | 4位 | 以 **4字节** 为单位，固定首部=5(20B)，最大15(60B) |
| **总长度** | 16位 | 首部+数据总长度(字节)，最大65535 |
| **标识** | 16位 | 同一数据报的所有分片标识相同 |
| **标志** | 3位 | DF=1禁止分片；MF=1后面还有分片 |
| **片偏移** | 13位 | 分片在原数据报中的位置，**以8字节为单位** |
| **TTL** | 8位 | 每过路由器-1，到0丢弃 |
| **协议** | 8位 | TCP=6, UDP=17, ICMP=1 |

**IP分片计算**（以太网 MTU = **1500字节**）：
```
原始数据报总长4000B（首部20B+数据3980B），MTU=1500B

分片1：首部20B + 数据1480B = 1500B, MF=1, 片偏移=0
分片2：首部20B + 数据1480B = 1500B, MF=1, 片偏移=185（1480/8）
分片3：首部20B + 数据1020B = 1040B, MF=0, 片偏移=370（2960/8）
```
> 注意：分片数据部分必须是8的整数倍
>
> ⚠️ **片偏移只标记数据部分**在原始数据报中的起始位置（除以8后的值）。分片到达接收端后，**去掉每个分片的临时首部**，只将数据块按片偏移顺序拼接，恢复原始数据报。

### 3. 划分子网、CIDR路由聚合（⚠️ **必考计算**）

**子网地址** = IP地址 AND 子网掩码
**广播地址** = 子网地址 OR (NOT 子网掩码)

| 类别 | 默认掩码 |
|:----:|:---------:|
| A类 | 255.0.0.0 (/8) |
| B类 | 255.255.0.0 (/16) |
| C类 | 255.255.255.0 (/24) |

```
子网数 = 2^(借用主机位数)
每个子网主机数 = 2^(剩余主机位数) - 2
```

**CIDR记法**：`a.b.c.d/n`，网络前缀越短地址块越大
**路由聚合**：将多个连续子网合并（如 128.10.0.0/24~128.10.3.0/24 → 128.10.0.0/22）

### 4. IP地址与MAC地址				

**IP地址**（网络层，逻辑地址） vs **MAC地址**（数据链路层，物理地址）
**ARP协议**：将**同一局域网内**的IP地址解析为MAC地址

### 5. IP层转发分组的过程，最长匹配原则（⚠️ **重要**）

转发表存储（目的网络地址 + 下一跳地址）

**最长前缀匹配**：选择前缀最长（最具体）的匹配条目

```
转发顺序：主机路由(/32) → 网络路由(最长匹配) → 默认路由(0.0.0.0/0)
```

### 6. 数据层面和控制层面

**数据层面**：根据转发表转发数据报 | **控制层面**：构建和更新转发表

### 7. ARP协议（⚠️ **重要**）

**ARP高速缓存**：存放IP→MAC映射，动态更新

**工作流程**：
1. A查ARP缓存，有B的MAC则直接发送
2. 查不到 → A**广播**ARP请求
3. B**单播**ARP响应（写入自己的MAC）
4. A将映射写入缓存

> ARP请求是**广播**，响应是**单播**，只适用于**同一局域网**

### 8. RIP协议（⚠️ **重要**）

**距离向量**路由协议，**跳数**为度量，最大15（16=不可达）

**三个特点**：
1. 仅和**相邻路由器**交换信息
2. 交换**全部路由表**
3. 每**30秒**固定交换

**更新规则**（收到相邻路由器X的报文）：
1. 修改：下一跳= X，距离+1
2. 对每个项目（目的网络N，距离d）：
   - 表中**无N** → 加入
   - 下一跳是**X** → 替换
   - 下一跳不是X且 d < 表中距离 → 更新

**超时**：3分钟没收到更新 → 距离置为16

> **缺点**：跳数限制15，收敛慢，"好消息快坏消息慢"

见【第三章 第6节 VLAN】

## 第五章 运输层

### 1. TCP首部格式：序号、确认号

**首部固定20字节**，选项最长40字节，总长20~60字节。

| 关键字段 | 长度 | 说明 |
|:--------:|:----:|------|
| **序号(seq)** | 4字节 | 本报文段数据的**第一个字节**序号 |
| **确认号(ack)** | 4字节 | **期望收到**的下一个字节序号 |
| **SYN** | 1位 | =1 连接请求/接受 |
| **ACK** | 1位 | =1 确认号有效，连接建立后必须为1 |
| **FIN** | 1位 | =1 数据发完，释放连接 |
| **窗口** | 2字节 | 接收方允许对方发送的数据量（流量控制） |

### 2. 停止等待协议效率

每发一个分组等确认，收确认再发下一个。

**信道利用率**：U = T_D / (T_D + RTT + T_A)

各符号含义：

| 符号 | 全称 | 含义 |
|:----:|:----:|------|
| **T_D** | Transmission Delay | **发送时延**，数据帧长度 / 发送速率 |
| **RTT** | Round-Trip Time | **往返时间**，从发完数据到收到确认，主要是传播时延×2 |
| **T_A** | Acknowledgment Delay | **确认帧的发送时延**，确认帧长度 / 发送速率 |

> 信道利用率 = 真正传数据的时间 / 传一轮的总时间。停止等待协议信道利用率通常很低，因为大部分时间在空等确认。

### 3. "以字节为单位的滑动窗口"机制

**流量控制**：让发送方不要太快，确保接收方来得及接收

**实际发送窗口 = Min(rwnd, cwnd)**

发送方实际能一口气发多少数据，由两个窗口共同限制，取**较小值**：

| 窗口 | 全称 | 含义 | 控制方 | 类比 |
|:----:|:----:|------|:------:|------|
| **rwnd** | receiver window（接收窗口） | 接收方还剩多少缓存空间 | 接收方通告 | 碗还能装多少菜 |
| **cwnd** | congestion window（拥塞窗口） | 网络当前是否通畅 | 发送方探测 | 路况堵不堵 |

> 接收方处理不过来 → rwnd 变小 → **流量控制**
> 网络出现丢包 → cwnd 自动减小 → **拥塞控制**

### 4. TCP拥塞控制（⚠️ **必考**）

**拥塞判断信号**：
- **超时**（严重）：包丢了且没收到任何确认，说明网络几乎断了
- **3个重复ACK**（轻度）：收到了ACK确认，只是有零星丢包，网络还能用

**两种状态**：

| 阶段 | 条件 | cwnd 变化 | 特点 |
|:----:|:----:|:---------:|:----:|
| **慢开始** | cwnd < ssthresh | **指数增长**（1→2→4→8→...） | 每经过一个 RTT，cwnd 翻倍 |
| **拥塞避免** | cwnd ≥ ssthresh | **线性增长**（每 RTT + 1） | 增长变缓，保守探测 |

> ❓ **为什么拥塞避免阶段 cwnd 还要继续增加？** —— 因为网络状况是动态变化的。上一秒拥塞，下一秒可能有其他连接释放了带宽。如果 cwnd 到 ssthresh 就锁死，网络变好了也感知不到，白白浪费可用带宽。所以拥塞避免的策略是**谨慎地线性增长，试探当前网络的真实上限**，直到出现丢包信号才降速。"拥塞避免"不是"停止增长"，而是"从莽撞翻倍转为小心试探"。

**拥塞发生时的反应**：

| 事件 | 严重程度 | ssthresh（新阈值） | cwnd（新窗口） | 进入什么阶段 |
|:----:|:--------:|:------------------:|:--------------:|:-----------:|
| **超时** | ❗严重 | max(cwnd/2, 2) | 降为 **1** | **慢开始**（从头来过） |
| **3重复ACK** | ⚠️轻度 | = **cwnd/2** | = 新 **ssthresh** | **拥塞避免**（直接恢复） |

> **速记**：超时严重 → 阈值减半、窗口归1、重走慢开始；3重复ACK轻度 → 阈值减半、窗口降到阈值、直接拥塞避免。

### 5. TCP连接管理（三次握手、四次挥手）（⚠️ **重要**）

#### 三次握手

```
客户端                             服务器
  │-------- SYN=1, seq=x ----------→│  ① SYN
  │←-- SYN=1, ACK=1, seq=y, ack=x+1-│  ② SYN+ACK
  │-------- ACK=1, seq=x+1 --------→│  ③ ACK
```

#### 四次挥手

```
客户端                             服务器
  │-------- FIN=1, seq=u ----------→│  ① FIN
  │←-- ACK=1, ack=u+1 --------------│  ② ACK
  │       (服务器还可能发数据...)      │
  │←-- FIN=1, ACK=1, seq=w, ack=u+1-│  ③ FIN+ACK
  │-------- ACK=1, seq=u+1, ack=w+1→│  ④ ACK
  │       (等待2MSL后关闭)           │
```

> **为什么三次握手？** 防止已失效的连接请求到达服务器导致资源浪费
> **为什么四次挥手？** 全双工需各自关闭；服务器收到FIN可能还有数据要发
> **为什么2MSL？** 确保最后一个ACK能到达 + 确保所有报文段消失

### 一、数据链路层 (Data Link Layer)

#### 1. 循环冗余校验 (CRC) 计算 - 基础填空
*   **【原题】**：待发送信息为 `110011`，生成多项式为 $x^4+x^3+x^2+x^0$，校验序列 FCS 为 (1)_______。
*   **【解析】**：
    1.  **确定除数**：生成多项式 $x^4+x^3+x^2+x^0$ 转化为二进制。$x^4(1), x^3(1), x^2(1), x^1(0), x^0(1)$，即 `11101`。
    2.  **被除数补零**：多项式最高阶为 4，在信息码 `110011` 后补 4 个 0，得到 `1100110000`。
    3.  **模 2 除法**：用 `1100110000` ÷ `11101`（进行异或运算，不进位不借位）。
*   **【答案】**：**`0110`** （注：图中填写的 1100 错误）。

#### 2. 循环冗余校验 (CRC) 综合分析题
*   **【原题】**：要发送的数据为 `1101011011`。采用 CRC 的生成多项式是 $P(X) = X^4+X+1$。试求应添加在数据后面的余数。数据在传输过程中最后一个 `1` 变成了 `0`，问接收端能否发现？若数据在传输过程中最后两个 `1` 都变成了 `0`，问接收端能否发现？采用 CRC 检验后，数据链路层的传输是否就变成了可靠的传输？
*   **【解析】**：
    1.  **求余数**：除数为 `10011`，被除数补 4 个 0 为 `11010110110000`。经计算余数为 **`1110`**。
    2.  **检错能力**：CRC 能够检测出所有的单比特错误。由于该生成多项式能够检测出所有长度小于等于 4 的突发错误，因此最后两个 `1` 变 `0`（双比特错误）也 **能被发现**。
    3.  **可靠传输判定**：**不能**。CRC 只能保证接收方收到的帧在传输过程中没有产生差错（即"无差错接受"）。可靠传输还需要解决"丢包、重复、乱序"等问题，这通常需要确认和重传机制。
*   **【答案】**：余数 `1110`；两种情况均能发现错误；CRC 不能使数据链路层变为可靠传输。

#### 3. 字节填充 (Byte Stuffing) 算法
*   **【原题】**：一个数据流中出现了这样的数据段：`A B ESC ESC C ESC ESC ESC FLAG ESC FLAG D`，采用字节填充算法，请问经过填充之后的输出是什么？
*   **【解析】**：规则是在每一个控制字符（`ESC` 或 `FLAG`）前面插入一个转义字符 `ESC`。
*   **【答案】**：**`A B ESC ESC ESC ESC C ESC ESC ESC ESC ESC ESC ESC FLAG ESC ESC FLAG D`**。

#### 4. 零比特填充 (Bit Stuffing) 算法
*   **【原题】**：需要在数据链路层上发送一个比特串：`0111101111101111110`，试问经过零比特填充之后实际发送出去的是什么？
*   **【解析】**：规则是"逢五填零"——只要发现连续的 5 个 `1`，就在其后强行插入一个 `0`。
*   **【答案】**：**`011110111110011111010`**。

#### 5. 以太网交换机自学习
*   **【原题】**：为简单起见，主机 A, B, C, D, E, F, G, H 的 MAC 地址与其主机名称相同。主机间依次如下通信：1. B→C, 2. D→A, 3. G→D, 4. E→H, 5. C→B, 6. F→G。请给出以太网交换机 1, 2, 3 的自学习过程以及各自最终的帧交换表的内容。
*   **【解析】**：交换机每收到一个帧，就记录其【源 MAC 地址】和【进入端口】。如果目的地址不在表中，则转发到除源端口外的所有端口。
*   **【答案】**：最终各交换机表中会记录所有通信过的主机与其物理连接端口的对应关系。

### 二、网络层 (Network Layer)

#### 6. CIDR 子网划分计算
*   **【原题】**：某单位分配到一个地址块 `136.23.12.64/26`。现在需要进一步划分为 4 个一样大的子网。试问：
    (1) 每一个子网的网络前缀有多长？
    (2) 每一个子网中有多少个可用地址？
    (3) 每一个子网的地址分别是？
*   **【解析】**：
    1.  划分为 4 个子网需要借 2 位主机位 ($2^2=4$)。原前缀 26，新前缀为 $26+2=28$。
    2.  主机位剩余 $32-28=4$ 位。总地址 $2^4=16$，可用地址为 $16-2=14$。
    3.  每个子网的地址跨度（步长）为 $2^4=16$。
*   **【答案】**：(1) **28**； (2) **14**； (3) **`136.23.12.64/28; 136.23.12.80/28; 136.23.12.96/28; 136.23.12.112/28`**。

#### 7. 基础子网计算
*   **【原题】**：已知某个网络的地址为 `218.75.230.0`，使用子网掩码 `255.255.255.192` 对其进行子网划分。子网数量为 (1)_______，每个子网可分配的地址数量为 (2)_______。
*   **【解析】**：
    1.  C 类地址默认掩码 `/24`。`192` 二进制为 `11000000`，借了 2 位主机位。子网数 $= 2^2 = 4$。
    2.  主机位剩余 6 位。可用地址数 $= 2^6 - 2 = 62$。
*   **【答案】**：(1) **4**； (2) **62**。

#### 8. IP 数据报分片计算
*   **【原题】**：一个数据报长度为 4000 字节（固定首部长度）。现在经过一个网络传送，但此网络能够传送的最大数据长度（MTU）为 1500 字节。试问：
    应当划分为 (1)_______ 个短些的数据报片；第 2 个数据报片的数据字段长度为 (2)_______ 个字节、片偏移字段为 (3)_______，MF 标志应为 (4)_______，DF 标志应为 (5)_______。
*   **【解析】**：
    1.  总载荷 $= 4000-20=3980$。最大载荷 $= 1500-20=1480$（必须是 8 的倍数）。
    2.  分片 1 (1480)，分片 2 (1480)，分片 3 (1020)。共 3 片。
    3.  片偏移单位是 8 字节。第 2 片偏移 $= 1480 / 8 = 185$。
*   **【答案】**：(1) **3**； (2) **1480**； (3) **185**； (4) **1**； (5) **0**。

#### 9. 路由表转发查找（⚠️ **常考**）
*   **【原题】**：设某路由器建立了如下路由表：

    | 目的网络 | 子网掩码 | 下一跳 |
    |:--------:|:--------:|:------:|
    | 128.96.39.0 | 255.255.255.128 | 接口 m0 |
    | 128.96.39.128 | 255.255.255.128 | 接口 m1 |
    | 128.96.40.0 | 255.255.255.128 | R2 |
    | 192.4.153.0 | 255.255.255.192 | R3 |
    | *（默认） | — | R4 |

    现收到 2 个分组，目的 IP 如下，计算从哪个接口转发：
    (1) `128.96.40.12`
    (2) `128.96.40.151`

*   **【解析】**（**最长前缀匹配，逐条与运算**）：

    **分组 (1)：128.96.40.12**

    将目的 IP 与每条路由的**子网掩码**做逐位"与"运算，得到**目的网络地址**，再对比路由表中的目的网络：

    | 对比路由 | 与运算过程 | 得到网络地址 | 匹配？ |
    |:--------:|:----------:|:------------:|:------:|
    | ① 128.96.39.0/25 | 128.96.40.12 AND 255.255.255.128 | 128.96.40.0 | ❌ ≠ 128.96.39.0 |
    | ② 128.96.39.128/25 | 128.96.40.12 AND 255.255.255.128 | 128.96.40.0 | ❌ ≠ 128.96.39.128 |
    | ③ 128.96.40.0/25 | 128.96.40.12 AND 255.255.255.128 | **128.96.40.0** | ✅ **匹配** |
    | ④ 192.4.153.0/26 | 128.96.40.12 AND 255.255.255.192 | 128.96.40.0 | ❌ ≠ 192.4.153.0 |

    匹配到第③条（128.96.40.0/25），下一跳为 **R2**。

    **分组 (2)：128.96.40.151**

    | 对比路由 | 与运算过程 | 得到网络地址 | 匹配？ |
    |:--------:|:----------:|:------------:|:------:|
    | ① 128.96.39.0/25 | 128.96.40.151 AND 255.255.255.128 | 128.96.40.128 | ❌ ≠ 128.96.39.0 |
    | ② 128.96.39.128/25 | 128.96.40.151 AND 255.255.255.128 | 128.96.40.128 | ❌ ≠ 128.96.39.128 |
    | ③ 128.96.40.0/25 | 128.96.40.151 AND 255.255.255.128 | 128.96.40.128 | ❌ ≠ 128.96.40.0 |
    | ④ 192.4.153.0/26 | 128.96.40.151 AND 255.255.255.192 | 128.96.40.128 | ❌ ≠ 192.4.153.0 |

    所有具体路由均不匹配 → 走**默认路由**，下一跳为 **R4**。

    > 💡 **关键易错点**：不要被 `.40.151` 的第三个数字 `40` 迷惑以为匹配第③条——与掩码 `255.255.255.128` 做与运算后得到的是 `128.96.40.128`，而不是 `128.96.40.0`。因为 151 的二进制是 `10010111`，与 `10000000`（128）按位与得 `10000000` = 128 ≠ 0。

*   **【答案】**：(1) **R2**；(2) **R4**。

#### 10. RIP 路由协议更新 (距离向量算法)
*   **【原题】**：假定路由器 B 的路由表有如下项目（N1 7 A, N2 2 C, N6 8 F, N8 4 E, N9 4 F）。现在 B 收到从 C 发来的路由信息（N2 4, N3 8, N6 4, N8 3, N9 5）。试求出路由器 B 更新后的路由表。
*   **【解析】**：对 C 传来的信息先将距离 +1，下一跳设为 C。再对比 B 原表：
    *   相同下一跳：强制更新。
    *   不同下一跳：距离变短则更新，否则不改。
    *   新路径：添加。
*   **【答案】**：
    - N1: **7, A**（只有 B 原表有，不变）
    - N2: **5, C**（相同目的 N2，C 是原下一跳，强制更新）
    - N3: **9, C**（新路径，添加）
    - N6: **5, C**（不同下一跳，距离 5 < 8，更新）
    - N8: **4, E**（不同下一跳，距离 4 = 4，不变）
    - N9: **4, F**（不同下一跳，距离 6 > 4，不变）
