## 一、数据库系统概述

### 1.1 基本概念

- **数据**：描述事物的符号记录。**数据库 DB**：长期存储、有组织、可共享的数据集合。
- **DBMS**：管理数据库的系统软件（MySQL、PostgreSQL、Oracle）。**DBS = DB + DBMS + 应用 + 用户**。

### 1.2 三级模式与两级映像【必考】

```
用户 ── 外模式（视图）      ┐
        ├ 外模式/模式映像   │ 逻辑独立性：模式变，外模式不变
       模式（全局逻辑结构）  ┘
        ├ 模式/内模式映像    │ 物理独立性：存储变，模式不变
       内模式（物理存储）
```

- **逻辑独立性**：模式改变时，调整外模式/模式映像，应用程序不必改。
- **物理独立性**：存储结构改变时，调整模式/内模式映像。

### 1.3 数据模型三要素

数据结构、数据操作、完整性约束。常见模型：层次、网状、**关系**、面向对象。

## 二、关系模型与关系代数【必考】

### 2.1 关系的基本术语

| 术语 | 含义 |
|------|------|
| 域 | 属性的取值集合 |
| 笛卡尔积 | D₁×D₂×…×Dₙ 所有元组组合 |
| 候选码 | 能唯一标识元组且无多余属性的最小属性集 |
| 主码 | 从候选码中选定的一个 |
| 外码 | 本关系中取值引用另一关系主码的属性组 |
| 分量原子性 | 关系中每个分量必须是不可分的数据项（1NF 前提） |

关系是元组的**集合**——天然去重，无序。

### 2.2 五种基本关系代数运算【必考】

设关系 R、S，属性 A：

1. **选择 σ<sub>A='x'</sub>(R)**：按条件选**行**。
2. **投影 π<sub>A</sub>(R)**：取指定**列**，自动去重。
3. **并 ∪ / 差 −**：要求 R 与 S **同目**（属性个数相同且对应域相容）。
4. **笛卡尔积 ×**：R×S 的元组两两拼接，结果属性数 = R+S。
5. **连接 ⋈**：
   - θ 连接：按条件拼接；
   - **等值连接**：θ 为 =，保留重复列；
   - **自然连接**：比较同名属性相等并**去掉重复列**。

### 2.3 除法 ÷【必考小题】

R ÷ S：找出 R 中"对 S 的**全部**取值都有匹配"的元组分量。语义对应 SQL 中"查询选修了**所有**课程的学生"。手算技巧：逐个候选元组检查其象集是否包含 S 的全部值。

### 2.4 象集与元组演算

X 的象集 Z<sub>x</sub>：R 中 x 分量值为 X 的元组在另一属性组上的取值集合。除法判定即"Z<sub>x</sub> ⊇ S 的投影？"。

## 三、SQL 语言【必考】

### 3.1 查询核心句型

```sql
SELECT [DISTINCT] 列
FROM 表 [别名]
[WHERE 行过滤]
[GROUP BY 分组列 [HAVING 组过滤]]
[ORDER BY 排序列 [ASC|DESC]]
[LIMIT n OFFSET m];
```

执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT。

**易错点**：WHERE 里不能写聚合函数；分组后非聚合列必须出现在 GROUP BY 中。

### 3.2 高频查询题型模板

```sql
-- ① 最高分学生（子查询 vs 连接两种写法都要会）
SELECT sno, grade FROM SC
WHERE cno='C01' AND grade = (SELECT MAX(grade) FROM SC WHERE cno='C01');

-- ② 至少选修了两门课的学生
SELECT sno FROM SC GROUP BY sno HAVING COUNT(*) >= 2;

-- ③ 选修了全部课程的学生（存在量词双重否定）
SELECT sname FROM Student S
WHERE NOT EXISTS (
  SELECT * FROM Course C
  WHERE NOT EXISTS (
    SELECT * FROM SC WHERE SC.sno=S.sno AND SC.cno=C.cno));

-- ④ 多表连接：学生姓名+课程名+成绩
SELECT S.sname, C.cname, SC.grade
FROM Student S JOIN SC ON S.sno=SC.sno
              JOIN Course C ON SC.cno=C.cno;

-- ⑤ LEFT JOIN 找没有选课的学生
SELECT S.sname FROM Student S
LEFT JOIN SC ON S.sno=SC.sno
WHERE SC.sno IS NULL;
```

NULL 判定只能用 `IS NULL / IS NOT NULL`；`COUNT(*)` 统计行数，`COUNT(col)` 不计 NULL。

### 3.3 DDL 与 DML

```sql
CREATE TABLE Student (
  sno CHAR(10) PRIMARY KEY,
  sname VARCHAR(20) NOT NULL,
  sage SMALLINT CHECK (sage BETWEEN 14 AND 45),
  dno CHAR(4),
  FOREIGN KEY (dno) REFERENCES Dept(dno) ON DELETE SET NULL
);

CREATE VIEW v_pass AS
  SELECT sno, AVG(grade) avg_g FROM SC GROUP BY sno HAVING AVG(grade)>=60;
-- 视图是虚表，不存数据；带聚合/GROUP BY/DISTINCT 的视图默认不可更新

ALTER TABLE Student ADD email VARCHAR(50);
DROP TABLE Student CASCADE;   -- RESTRICT 有依赖则拒删
```

索引：`CREATE INDEX idx_name ON Student(sname);`
适合建索引：频繁出现在 WHERE/JOIN/ORDER BY 的列；不适合：更新极频繁、基数低的列（如性别）、很少查询的表。

### 3.4 权限控制【常考】

```sql
GRANT SELECT, INSERT ON SC TO U1 WITH GRANT OPTION;  -- 允许转授
REVOKE INSERT ON SC FROM U1 CASCADE;                  -- 级联收回转授出去的权限
```

角色：`CREATE ROLE r_teacher; GRANT ... TO r_teacher; GRANT r_teacher TO U2;`

## 四、数据库完整性

| 类型 | 防护对象 | 实现手段 |
|------|------|------|
| 实体完整性 | 主码唯一且非空 | PRIMARY KEY |
| 参照完整性 | 外码引用有效或为 NULL | FOREIGN KEY + 触发动作 |
| 用户定义完整性 | 业务规则 | NOT NULL、UNIQUE、CHECK |

参照完整性触发动作：`ON DELETE {RESTRICT | CASCADE | SET NULL | NO ACTION}`。
断言 ASSERTION 与触发器 TRIGGER（BEFORE/AFTER + OLD/NEW 行变量）用于跨表复杂约束。

## 五、关系数据理论（范式）【必考·大题】

### 5.1 函数依赖术语

- X→Y：Y 函数依赖于 X。**完全/部分**依赖：Y 是否依赖 X 的真子集。
- **传递依赖**：X→Y，Y↛X，Y→Z ⇒ Z 传递依赖 X。
- Armstrong 公理：自反、增广、传递 + 合并/分解/伪传递推理规则。
- **闭包 X⁺**：反复用公理能推出的全部属性。求候选码：只在左端出现的属性必在候选码中；只在右端出现的不在。

### 5.2 各范式定义与判定【必考】

| 范式 | 定义（通俗版） | 消除的问题 |
|------|------|------|
| 1NF | 所有属性原子、不可再分 | 非原子字段 |
| 2NF | 消除非主属性对码的**部分**函数依赖 | 组合码下部分依赖 |
| 3NF | 消除非主属性的**传递**依赖 | 传递依赖 |
| BCNF | 每个**决定因素**都包含码（比 3NF 更严） | 主属性间的依赖 |

判定流程（大题模板）：

1. 写出所有函数依赖，找候选码。
2. 区分主属性 / 非主属性。
3. 逐条检查是否存在部分依赖（→2NF 问题）、传递依赖（→3NF 问题）、决定因素不含码（→BCNF 问题）。
4. 给出最高满足的范式级别并说明理由。

### 5.3 模式分解

- **无损连接**：分解后能通过自然连接恢复原关系不增信息。判别法：Chase 表格法（αβ 法）；二分性质：R1∩R2 → (R1−R2) 或 → (R2−R1) 成立则无损。
- **保持依赖**：原 FD 都可在某个分区的投影内被检验。
- 结论记忆：**3NF 可以同时做到无损 + 保持依赖；BCNF 保证无损但不一定保持依赖**。
- 分解示例：SC(Sno,Cno,Sname,Grade)，若 Sno→Sname 存在部分依赖 → 拆成 S(Sno,Sname) 与 SC(Sno,Cno,Grade)。

### 5.4 反范式化

实际系统为减少连接、提高读性能，允许适度冗余（如订单表冗余商品名），属于空间换时间的工程权衡——考试答理论要规范化，工程题要辩证。

## 六、事务与并发控制【必考】

### 6.1 事务 ACID

| 特性 | 含义 | 靠什么实现 |
|------|------|------|
| 原子性 A | 全做或全不做 | undo 日志回滚 |
| 一致性 C | 从一个一致状态到另一个 | 是目标，由 A/I/D 共同保障 |
| 隔离性 I | 并发事务互不干扰 | 锁 / MVCC |
| 持久性 D | 提交后永久生效 | redo 日志（WAL 先写日志） |

### 6.2 并发三大异常【必考】

1. **丢失修改**：两事务同时写同一数据，后写覆盖先写。
2. **读脏数据**：读到未提交事务修改后的值，对方回滚。
3. **不可重复读**：同一事务两次读同一数据结果不同（含幻读：两次范围查询行数不同）。

### 6.3 封锁协议与两段锁【必考】

- 锁类型：S 锁（共享读，读读兼容）、X 锁（排他写，与任何锁冲突）。兼容矩阵必背。
- 三级封锁协议：
  - 一级：修改前加 X 直到结束 → 不丢失修改；
  - 二级：一级 + 读前加 S 读后即放 → 不读脏；
  - 三级：一级 + 读前加 S 直到事务结束 → 可串行化、无不可重复读。
- **两段锁协议 2PL**：生命周期分扩展段（只能加锁）与收缩段（只能解锁），交点后不得再加锁。**遵守 2PL ⇒ 冲突可串行化**；反之不成立。2PL 不能避免死锁。

### 6.4 死锁处理

预防：一次性申请（破坏请求保持）、资源有序分配（破坏循环等待）。
检测：等待图有环即死锁；解除选择代价最小的牺牲者回滚。
超时法简单但可能误判。MySQL InnoDB 采用 wait-for 图检测 + 回滚代价小的事务。

### 6.5 隔离级别与 MVCC（加分项）

| 隔离级别 | 丢失修改 | 脏读 | 不可重复读 | 幻读 |
|------|:---:|:---:|:---:|:---:|
| READ UNCOMMITTED | 可能 | 可能 | 可能 | 可能 |
| READ COMMITTED | 避免 | 避免 | 可能 | 可能 |
| REPEATABLE READ | 避免 | 避免 | 避免 | InnoDB 基本避免 |
| SERIALIZABLE | 避免 | 避免 | 避免 | 避免 |

MVCC 思想：每行保存多版本（创建/删除事务号），读操作不加锁读历史版本，实现"读写不阻塞"，是 RC/RR 级别的底层机制。

## 七、数据库恢复技术【必考】

### 7.1 日志与检查点

- 日志记录格式：<事务 T，操作对象，旧值，新值>。
- **先写日志 WAL**：修改页之前先把日志写到稳定存储——undo 的前提。
- redo 用于已提交未落盘的重做（前滚）；undo 用于未提交事务撤销（后滚）。
- **检查点 checkpoint**：周期性把日志缓冲与脏页刷盘并在日志写入检查点记录，缩短故障恢复时需扫描的日志区间。

### 7.2 故障恢复策略【必考大题】

给定日志序列（T1 begin/update/commit…T2 …）与检查点位置，回答重启后对每个事务做 REDO 还是 UNDO：

1. 检查点前已提交 → 无需处理（已落盘）。
2. 检查点后提交 → **REDO**（正向重做全部操作）。
3. 尚未提交（无 commit 记录）→ **UNDO**（反向恢复旧值）。

原则："**先 REDO 后 UNDO**"，因为 redo 只看 commit 标志、undo 处理剩余活跃事务。

## 八、数据库设计（E-R 模型）【常考大题】

### 8.1 设计六阶段

需求分析 → 概念结构设计（E-R 图）→ 逻辑结构设计（转关系模式）→ 物理设计 → 实施 → 运维。

### 8.2 E-R 图要素与冲突

实体（矩形）、属性（椭圆）、联系（菱形），联系可带属性；标注 1:1 / 1:n / m:n。
合并局部 E-R 图的三类冲突：属性冲突、命名冲突、结构冲突（解决：统一口径、抽象/拆分实体）。

### 8.3 E-R 转关系模型规则【必考】

| 联系类型 | 转换方法 |
|------|------|
| 1:1 | 任选一端把另一端主码作为外键 |
| 1:n | 把 **1 端主码放入 n 端**作外键（联系属性一并放入 n 端） |
| m:n | **单独建关系**，主码 = 两端主码组合，联系属性附加 |
| 三元联系 | 一般单独建表，主码为三个实体的码组合 |

冗余优化：合并具有相同码的关系模式；1:1 且参与度满时可并入一端。

## 常见问题

### 自然连接和等值连接的区别？

等值连接按任意同名列相等拼接且保留两份重复列；自然连接自动比较**所有同名属性**并去掉重复列。若两表无公共属性，自然连接退化为笛卡尔积。

### 为什么 2PL 能保证可串行化但不能避免死锁？

可串行化的充分条件来自"事务间冲突操作的次序与其加锁点次序一致"；而扩展段持锁等待对方收缩段释放时，双方互相等待仍会成环——死锁防护需要额外机制（超时/等待图）。

### 候选码求解有什么套路？

① 只出现在 FD 左端的属性 → 必属候选码；② 只在右端 → 必不属于；③ 左右都不出现 → 属于每个候选码；④ 两边都出现的逐一尝试。从"必属集合"出发求闭包，若未覆盖全属性再逐个加入第三类试探。

### 视图的好处？

简化查询（封装复杂连接）、安全隔离（只暴露授权列/行，配合权限）、逻辑独立性（基表重构时通过视图兼容旧应用）。代价：复杂视图查询性能差、嵌套视图不可更新限制。
